# TypeBoost

ひらがなを打って、変換せずに **Shift を2回押す**と、LLM が完成した文章に清書して置き換える Windows 用の常駐ツールです。

```
あしたのみーてぃんぐ15じ、じゃなくて16じにへんこうおねがい   ← 打つ（変換しない）
        ↓ Shift を2回
明日のミーティングを16時に変更お願いします。                 ← 置き換わる
```

音声入力ツールが速いのは、声だからではなく「雑に入力して LLM が清書する」からです。TypeBoost はそれをキーボードでやります。打ちながら考えられ、途中で直せて、職場でも無音で使えます。

> **現在の状態**: 動作検証用のスパイクです。Windows 専用で、LLM は Claude のみ対応しています。

## できること

- **変換操作が要らない**: スペースで変換して候補を選んで確定、という操作をまるごと省けます。
- **打ち間違いと言い直しを吸収する**: タイポや「〜じゃなくて」をBackspaceで直さず、そのまま打ち進められます。
- **口調を整える**: 既定の口調に加えて、アプリごとに口調を切り替えられます（Slack はカジュアル、メールは敬語、など）。
- **辞書**: 固有名詞の表記を固定したり、短い略記を展開したりできます（`おつ` → `お疲れ様です`）。
- **選択範囲の清書**: すでに書いた文章を選択して Shift を2回押すと、その部分を清書します。
- **取り消し**: 清書の直後にもう一度 Shift を2回押すと、元の文章に戻ります。
- **状態表示**: 画面下部に「清書中…」のピルが出て、結果がストリーミングで流れます。フォーカスは奪いません。

## 必要なもの

- Windows 11（WebView2 ランタイム。Windows 11 には標準で入っています）
- 日本語 IME（ローマ字入力）
- [Anthropic の API キー](https://platform.claude.com/)
- ビルド用: [Rust](https://rustup.rs/)（MSVC ツールチェーン）と [Node.js](https://nodejs.org/)

## セットアップ

### 1. ビルドする

```bash
npm install
npm run build
```

実行ファイルが `src-tauri/target/release/typeboost.exe` にできます。

### 2. API キーを設定する

API キーは環境変数から読み込みます。設定ファイルには保存しません。

```bash
setx ANTHROPIC_API_KEY "ここにキー"
```

キーがワークスペースに紐づいていない場合は、ワークスペース ID も必要です。設定画面の「一般」タブで入力するか、環境変数で指定します。

```bash
setx ANTHROPIC_WORKSPACE_ID "ここにワークスペースID"
```

`setx` の値は、すでに開いているターミナルやアプリには反映されません。新しいターミナルを開いてから起動してください。

### 3. 起動する

```bash
src-tauri\target\release\typeboost.exe
```

タスクトレイにアイコンが出れば起動しています。`--settings` を付けると、設定画面を開いた状態で起動します。終了はトレイアイコンの右クリックからです。

## 使い方

| やりたいこと | 操作 |
|---|---|
| 打った文章を清書する | IME オンでひらがなを打ち、**変換せずに** Shift を2回押す |
| 書いてある文章を清書する | 文章を選択して Shift を2回押す |
| 清書を取り消す | 清書の直後に、もう一度 Shift を2回押す |
| 清書を途中でやめる | 清書中に Esc を押す |

「2回押し」は、Shift を単独で押して離す操作を 0.35 秒以内に2回です。Shift+文字のような普段の使い方には反応しません。

清書中に打った文字は捨てられず、清書が終わったあとに順番どおり入力されます。

## 設定

トレイアイコンを右クリックして「設定…」を開きます。保存するとすぐ反映され、再起動は不要です。

| タブ | 項目 | 内容 |
|---|---|---|
| 口調 | 既定の口調 | 清書するときの文体。「丁寧」「カジュアル」「敬語メール」「変換のみ」の定型から選んで書き換えられます |
| 口調 | アプリ別の口調 | 実行ファイル名（例: `slack.exe`）ごとの口調。該当しないアプリでは既定の口調を使います |
| 口調 | 追加の指示 | 口調以外で常に守らせたいこと |
| 辞書 | 読み・略記 → 表記 | この読みが出てきたら必ずこの表記にします |
| 一般 | 清書のキー | Shift / Ctrl（左右の指定可）、または変換キー（JIS 配列） |
| 一般 | モデル | 既定は速度優先の `claude-haiku-5-5` |
| 一般 | ワークスペース ID | キーがワークスペースに紐づいていない場合のみ |

画面下部の「試す」にひらがなを打つと、保存前の設定で清書した結果と所要時間を確認できます。口調や辞書の調整に使ってください。

設定は `%APPDATA%\TypeBoost\config.json` に保存されます。

## 仕組み

Windows には、他のアプリの IME が持っている未確定文字列を外から読む方法がありません。そこで次の手順を取っています。

1. キーボードフックで打鍵を見て、ローマ字かな変換を自前で再現し、未確定文字列が何文字あるかを把握します。
2. Shift の2回押しを検知したら、Enter を送ってひらがなのまま確定します。
3. 確定した文字数ぶんを Shift+← で選択し直し、コピーして読み取ります。
4. 読み取った文字列が、手順1で追跡した内容と一致するかを照合します。一致しなければ何もせず中断します。
5. LLM に送り、結果を貼り付けて選択範囲を置き換えます。クリップボードは元の内容に戻します。

IME 自体は置き換えません。普段使っている IME（MS-IME、Google 日本語入力など）の上で動きます。

| ファイル | 役割 |
|---|---|
| `src-tauri/src/hook.rs` | キーボード/マウスフック、2回押しの検知、清書中の打鍵の保留 |
| `src-tauri/src/romaji.rs` | ローマ字かな変換の再現と、読み取り結果の照合 |
| `src-tauri/src/engine.rs` | 確定→読み取り→清書→置き換え→取り消しの流れ |
| `src-tauri/src/llm.rs` | プロンプトの組み立てと Claude API の呼び出し |
| `src-tauri/src/settings.rs` | 設定の読み書き |
| `src-tauri/src/pill.rs`, `ui/pill.html` | 状態表示のピル |
| `ui/settings.html` | 設定画面 |

## プライバシー

- **外部に送るもの**: 清書対象の文字列、口調、辞書、追加の指示だけです。送信先は Anthropic の API です。
- **打鍵の扱い**: 打鍵は未確定文字列を追跡するためにメモリ上でだけ保持し、確定のたびに破棄します。ファイルには書きません。
- **ログ**: `%LOCALAPPDATA%\TypeBoost\spike.log` に、所要時間と成否だけを記録します。入力内容は、環境変数 `TYPEBOOST_DEBUG` を設定したときだけ記録されます。
- **クリップボード**: 読み取りと貼り付けに一時的に使います。テキストは元に戻しますが、クリップボード履歴（Win+V）には清書結果が残ります。画像など、テキスト以外をコピーしていた場合は復元されません。

## 既知の制限

- **未確定中に変換やカーソル移動をすると清書できません**: スペース変換、矢印キー、Tab などを使ったあとは追跡できず、エラーを表示して中断します。ひらがなを打ったら、そのまま Shift を2回押してください。
- **ターミナルでは選択範囲の清書が無効です**: Ctrl+C が実行中のプログラムの中断になるためです。VS Code 内蔵のターミナルは判別できないので、そこでは使わないでください。
- **選択なしで Shift を2回押すと、行全体が対象になるエディタがあります**: VS Code など、選択なしの Ctrl+C が行コピーになるアプリが該当します。
- **JetBrains 系 IDE と衝突します**: Shift の2回押しが「どこでも検索」に割り当てられています。設定で清書のキーを右 Shift や Ctrl に変えてください。
- **応答に1秒強かかります**: 実測で、Shift の2回押しから置き換え完了まで 1.1〜1.4 秒です。
- **メモリ**: 本体は約 5MB ですが、ピル表示に使う WebView2 が約 160MB を使います。
- **Ctrl+V で貼り付けられないアプリでは動きません**。
- **かな入力（ローマ字入力以外）には対応していません**。

## 今後の予定

- OpenAI 互換 API とローカル LLM（Ollama など）への対応
- API キーを Windows の資格情報マネージャーに保存し、設定画面から入力できるようにする
- 入力欄の前後の文脈を渡して、同音異義語や人名の精度を上げる（オプトイン）
- 清書履歴と、修正からの辞書登録
- ピルの OS ネイティブ描画（メモリ削減）
- macOS 対応

## 開発

```bash
# ユニットテスト
cd src-tauri
cargo test
```

`scripts/sim.ps1` は、実際のテキスト欄にキー入力を送って動作を確かめるスクリプトです。指定したタイトルのウィンドウが前面にあるときだけキーを送ります。`TYPEBOOST_PROVIDER=mock` を設定して起動すると、API を呼ばずに「【清書】」を頭に付けるだけのモックで動作を確認できます。

```powershell
$env:TYPEBOOST_PROVIDER = 'mock'
src-tauri\target\release\typeboost.exe
notepad test.txt
.\scripts\sim.ps1 -Title 'test.txt' -Keys 'kyouhaiitenkidesune' -Undo
```
